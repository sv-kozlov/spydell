# Автономный прогон

Длительная работа без вмешательства владельца идёт только по контракту прогона. Нет контракта — обычный режим:
существенный выбор сразу уходит владельцу. Автономность не ослабляет ни одной проверки: ворота, программные проверки
и независимые ревьюеры работают как обычно.

## Контракт

Владелец просит автономную работу («автономно до конца волны 3»). Прогон начинается, когда на его критическом пути нет
открытых вопросов фронтира типа `grilling`; иначе сначала раунд опроса. Заполни контракт значениями по умолчанию,
покажи его владельцу один раз и после подтверждения запиши в карту решением с датой, раздел «Контракт прогона»
([artifacts.md](artifacts.md)). Изменение контракта — новое решение с датой.

| Поле | По умолчанию |
| --- | --- |
| Объём | Аналитика до changes, готовых к реализации: specs, технический дизайн, spec-review. Реализация волн — только если контракт её включает |
| Пробная единица | Первый прогон в проекте и первый с реализацией останавливаются после первой волны с отчётом; дальше — по лестнице доверия ниже |
| Делегированные решения | Тексты интерфейса в рамках глоссария, внутренние имена, структура тестов, рефакторинг внутри модуля, выбор между равноценными вариантами из уже подключённых библиотек, нарезка задач |
| Предварительный вариант за флагом | Запрещён |
| Git | Коммиты в рабочую ветку и их перекомпоновка до публикации. Push ветки, черновик PR и `--force-with-lease` собственной ветки после уборки — только если контракт разрешает |
| Разрешения | Сессии прогона работают без интерфейса и спросить владельца не могут. Правка файлов и команды из списка — git без push, тесты, `openspec`, `check.py` — в worktree; обход проверок — только во внешней песочнице. Строка запуска каждой среды берётся из `models.md` проекта и записывается сюда дословно, со всеми флагами разрешений и запретов; при запуске меняются только бриф, модель, effort и каталог. Флаги сред — [usage.md](usage.md), раздел «Запуск сессий» |
| Бюджет | Объём из первой строки, не больше трёх раундов на одни ворота, срок, деньги на прогон; лимит параллельных агентов — по [orchestration.md](orchestration.md). Где стоимость сессии не видна — лимит числа сессий |
| Срок зависания | 45 минут без побочных эффектов: строки журнала, коммита, изменения в worktree |
| Отчёт | Журнал прогона, отчёт после каждой волны, дайджест в конце |

Никогда не делегируются: видимое пользователю поведение, внешние контракты, данные и миграции, безопасность
и доступность, платные и внешние сервисы. Никогда не выполняются автономно: слияние, выкат, публикация, внешние
сообщения, действия с рабочими службами и приборами.

## Лестница доверия

- Понижение — следующий прогон останавливается после каждой волны, если в предыдущем владелец отменил решение агента,
  одни ворота провалились дважды после эскалации класса модели или строка запуска разошлась с контрактом.
- Повышение — следующий прогон идёт без остановки после первой волны, если предыдущий принят и ни одно условие
  понижения не сработало.
- Ступень записывается в контракт; владелец может назначить её сам, это решение с датой.

## Ход прогона

- Ведущий прогона — сессия, где подтверждён контракт. Волн он не ведёт: открывает ведущего каждой волны новой сессией
  с брифом по [orchestration.md](orchestration.md), по её итогу сверяет журнал с живым состоянием и открывает следующую.
  Средства запуска и запасной путь — [usage.md](usage.md), раздел «Запуск сессий».
- Живость держит наблюдатель, смысл решает ведущий. Запусти в фоне
  `python3 <spydell>/scripts/watch.py <комплект> --worktree <путь> --stuck-after <срок зависания>` — по `--worktree`
  на каждую живую сессию волны. Наблюдатель завершается событием, и это будит ведущего: `log` — новые строки журнала,
  сверь их с живым состоянием; `stuck` — у названных worktree нет побочных эффектов дольше срока, сними их сессии
  и перезапусти по причине провала ([orchestration.md](orchestration.md)); `restart` — плановый перезапуск через час,
  проверь прогон. После события запусти наблюдатель снова, с worktree сессий, которые живы сейчас.
- Каждую сессию ведущий запускает строкой из контракта. Отказ в разрешении — парковка или остановка; строку запуска
  меняет только владелец, изменением контракта.
- Решение из делегированного списка принимай сам и записывай в карту с кодом и пометкой «решено агентом».
- Решение вне списка — парковка: вопрос во фронтир с вариантами и рекомендацией, зависимые срезы — в `needs-decision`,
  независимая работа продолжается. Предварительный вариант за флагом — только если контракт его разрешает.
- Утверждение дизайна, QA-кейсы для человека и действия вне разрешённых паркуются так же.
- На каждой границе волны: `python3 <spydell>/scripts/check.py run <комплект>` сверяет строки запуска в журнале
  с контрактом — все флаги, кроме брифа, модели, effort, каталога, вывода и бюджета.

## Остановка

Останови прогон и напиши дайджест, если:

- одни ворота провалились дважды после эскалации класса модели;
- запаркованные решения блокируют большинство оставшихся срезов;
- исчерпан бюджет, в том числе деньги;
- следующий шаг требует действия вне разрешённых;
- строка запуска разошлась с контрактом;
- подтверждена находка уровня blocker о безопасности или данных.

## Журнал, отчёты, дайджест

- Журнал — `run-log.md` в комплекте: строка на решение, запуск сессии или ворота — время | волна и срез | что |
  почему | свидетельство | результат | модель, класс и effort. Строка запуска начинается в «что» со слова «запуск»,
  а в свидетельстве несёт фактическую строку запуска кодом и стоимость сессии, если она видна. Строка ворот несёт
  ревизию, на которой вынесен вердикт, число находок и принятых.
- После каждой волны — короткий отчёт владельцу: сделано и проверено, решения агента, запарковано, что дальше;
  дашборд обновлён ([artifacts.md](artifacts.md)).
- Дайджест в конце: что сделано и проверено (с ревизиями), решения агента с кодами (владелец может их отменить),
  запаркованные вопросы с рекомендациями, потраченные деньги или число сессий, «Не проверено». Отдельно помечай ворота
  без находок, ворота без принятых находок и вердикты не на итоговой ревизии. Сигналы для ретро — по
  [spydell-retro](../../spydell-retro/SKILL.md).
