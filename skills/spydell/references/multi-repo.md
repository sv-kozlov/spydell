# Работа в нескольких репозиториях

Применяй, когда изменение затрагивает больше одного git-репозитория: воркспейс из нескольких репозиториев,
общий store документов, несколько корней OpenSpec.

## Сколько церемоний

- Правка в двух репозиториях без изменения общего контракта — карта репозиториев одной строкой и SHA каждого в итоге.
- Изменение общего контракта или срез по нескольким репозиториям в волне — все правила ниже.

## Дом инициативы

Комплект `.spydell` (карта, требования, roadmap) живёт в одном репозитории: в общем store документов, если он есть,
иначе в мета-репозитории воркспейса или в репозитории-владельце продукта. Остальные репозитории только ссылаются на него.
Общий документ инициативы правит только ведущий.

## Карта репозиториев

В начале работы составь таблицу: репозиторий → роль в срезе → ветка → правила (AGENTS.md, навыки проекта, команда тестов).
Правила каждого репозитория применяй только к нему. В репозитории вне карты ничего не делай.

## Срез по нескольким репозиториям

- На каждый репозиторий со своим кодом — свой change; у всех один ID среза. Закрытие координирует один из них
  или документ приёмки в доме инициативы.
- Срез закрывается после проверки интегрированного результата, а не каждого change по отдельности.
- Один автор на репозиторий или набор файлов; параллельные сессии по разным репозиториям допустимы.

## Контракт первым

Общий контракт (API, protobuf, формат события) — контрактная зависимость в roadmap. Порядок: поставщик, затем потребитель;
если оба меняются в одной волне — expand–contract. Межрепозиторный контрактный или интеграционный тест входит в приёмку среза.

## Git

- В каждой git-команде указывай путь: `git -C <repo> …`.
- Проверку рабочей копии и сверку с upstream перед правками и коммитом делай в каждом репозитории карты.
- Коммиты и PR — отдельно по репозиториям, одно имя ветки на срез, PR ссылаются друг на друга.
- В документе приёмки — SHA каждого репозитория и проверенное сочетание версий.

## Слияние и выкат

В срезе зафиксируй порядок слияния и выката репозиториев и совместимые сочетания версий.
Если порядок нарушен, выкат следующего репозитория ждёт.

## Проверки на воротах

`openspec status` и `openspec validate --strict` с `--json` запускай в каждом корне OpenSpec среза, для общего store —
с `--store <id>`. `check.py` принимает несколько путей — по одному на репозиторий.
