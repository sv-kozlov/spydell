# Подробный уровень: чек-лист анализа

Читай, когда включён подробный уровень (строка в AGENTS.md проекта или просьба), когда ведущий передал задачу
с пометкой «читай подробный уровень» или когда одни и те же ворота анализа провалились дважды.

## Декомпозиция

- Отдели наблюдаемую проблему от заранее выбранного решения.
- Зафиксируй текущее состояние и траекторию без вмешательства.
- Назови участников, желаемое изменение, горизонт, область и ограничения.
- Разложи: результат → изменения → механизмы → действия → зависимости; каждый нижний уровень нужен верхнему.

## Утверждения

Для каждого решающего утверждения отметь тип: факт, причинный вывод, прогноз, оценка, ограничение, допущение, решение.
Запиши источник, свежесть, область применимости, уверенность, влияние на решение и способ проверки.
Вывод агента помечай отдельно.

## Причинная модель

Гипотеза: `вход → механизм → непосредственный результат → итоговый эффект`. Для каждого перехода — доказательства,
условия, конкурирующие объяснения, смешивающие факторы и наблюдение, которое её опровергнет. Обозначь границу модели.

## Данные и масштаб

- Происхождение, полнота, период, единицы, определения, сопоставимость; смещения отбора, выбросы, утечки.
- Нормализация — только по явному правилу.
- Агрегат разложи на компоненты и их вклад. Не смешивай запас и поток, мощность и загрузку, локальную скорость и итог.
- Отдели устойчивое от сезонности, разовых эффектов и низкой базы. Проверь знаменатели и уровни агрегации.

## Неопределённость и риски

- Диапазоны и сценарии вместо точечных чисел; порог, при котором выбор меняется.
- Неизвестное превращай в вопрос, исследование, прототип или эксперимент.
- Риск — сценарий «событие → механизм → последствие»: вероятность, тяжесть, ранний сигнал, предотвращение,
  запасной план, владелец. Проверь граничные значения, отказ зависимости, каскад и «метрика лучше, цель хуже».

## Проверка в реальности

`гипотеза → сигнал → способ измерения → срок → порог → продолжить / изменить / остановить / откатить`.
Предпочитай дешёвый обратимый прототип или пилот.

## Самопроверка

- Решение отвечает исходной проблеме; каждое существенное требование прослеживается до потребности и проверки.
- Промежуточные и конечные результаты не перепутаны; вывод не вырос из узкого примера.
- Что должно быть истинным, чтобы рекомендация была верна, и что заставит её пересмотреть.

## Реестры

Таблицы — когда повышают прослеживаемость: утверждение / тип / основание / уверенность / влияние / проверка;
допущение / диапазон / порог; риск / вероятность / сигнал / план / владелец; альтернатива / критерии / причина выбора;
гипотеза / метрика / цель / срок / правило решения.
