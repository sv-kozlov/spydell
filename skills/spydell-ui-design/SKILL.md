# Передача экрана во фронтенд

Если поручен только индекс, начни с [ведения индекса](references/design-index.md). Верни изменения, охват сверки
и затронутые экраны. Для передачи экрана используй `DESIGN.md`, индекс и требования к сценарию.
Если поручена сборка, сначала сверь охват индекса, затем собери экземпляры в `.pen` и проверь снимок фрейма.

1. Открой через MCP pen.dev нужный фрейм и его изображение. Сверь **визуальную вложенность** со слоями.
   Граница окна отделяет интерфейс от пояснений на холсте. При спорной вложенности проверь, что переключается
   вместе с вкладкой, прокручивается со списком или остаётся общим для окна. Если изображение недоступно,
   пометь дерево предварительным. Если слои расходятся с видимой группировкой, назови спорную ветвь.
2. Построй дерево «экран → область → составной компонент → значимый элемент». Ищи повторное использование
   сверху вниз: целое представление набора, затем коллекция, затем карточка. Общий компонент обоснуй общей
   задачей и структурой. Различия запиши в экземпляре как вариант, содержимое слота или переопределение.
   Повторяющийся элемент покажи один раз с правилом повтора.
3. Выбирай имя по предмету и роли. У иконки аудитории и кнопки её выбора разные имена и поведение.
   Сохрани фактическое имя в pen.dev, новое пометь как предложение. Связь с библиотекой подтверждай файлом
   и ID оригинала. Связь с кодом указывай только после проверки символа.

## Что передать

- **В ходе разбора** свяжи наблюдения и открытые вопросы с фреймом и состоянием. Согласованное решение
  владельца привяжи к существующей карте решений, если она ведётся.
- **Для повторного использования** сохрани запись общего компонента или токена в индексе.
  Правило берётся из `DESIGN.md`, адрес оригинала — из индекса, локальные отличия — из дерева.
  Формат, пример записи и обновление по разнице — в [справочнике](references/design-index.md).
- **Фронтенду** передай дерево и условия у соответствующих узлов. Например, диалог просмотра использует общее
  представление набора. Высота рассчитана на три ряда, с четвёртого прокручивается коллекция.
  Это даёт автору specs критерий, а QA — проверки на двух, трёх и четырёх рядах. Для точечной задачи достаточно чата.

## Ошибки, которые меняют результат

- В статье готовый список пропустили внутри группы и заменили полем с шевроном. Прежде чем предлагать замену,
  проверь нужную группу библиотеки. Недоступный источник оставь пробелом.
- В модерации стикеров общая панель действий визуально соседствует с вкладкой. Помести в ветвь вкладки
  только её содержимое. Авторское примечание рядом с окном может задавать правило для узла внутри окна.
