# Передача экрана во фронтенд

Ищи `design-index.md` в общем корне `.spydell` проекта, рядом с каталогами инициатив.
[Справочник индекса](references/design-index.md) задаёт выбор корня, формат и порядок сверки.

- **Создай** файл по запросу на индекс или перед первой сборкой экрана из общей библиотеки, если файла ещё нет.
  Для разового разбора снимка достаточно дерева в ответе.
- **Обнови** проверенные записи при изменении оригинала, варианта, токена, адреса либо при обнаружении пропуска.
  Перед серией экранов и передачей в разработку сверь используемую часть. При совпадении содержания и ревизии
  оставь файл без правок. Для поручения «только индекс» верни разницу, охват и затронутые экраны.

Для передачи экрана используй `DESIGN.md`, индекс и требования к сценарию.
При сборке сверь охват индекса, используй оригиналы компонентов и осмотри готовый макет или прототип.

1. Открой нужное состояние экрана. Сверь **визуальную вложенность** с доступным деревом слоёв или компонентов.
   Примечание за границей окна может описывать поведение узла внутри. При спорной вложенности проверь, что переключается
   вместе с вкладкой, прокручивается со списком или остаётся общим для окна. Если изображение недоступно,
   пометь дерево предварительным. По одному снимку можно предложить структуру, но нельзя подтвердить связи
   с библиотекой. Если слои расходятся с видимой группировкой, назови спорную ветвь.
2. Построй дерево «экран → область → составной компонент → значимый элемент». Ищи повторное использование
   сверху вниз: панель выбора, список, отдельная строка. Общий компонент обоснуй общей
   задачей и структурой. Различия запиши в экземпляре как вариант, содержимое слота или переопределение.
   Повторяющийся элемент покажи один раз с правилом повтора.
3. Выбирай имя по предмету и роли. Индикатор состояния и кнопка его смены могут выглядеть одинаково.
   Сохрани имя из источника, предложенное имя пометь отдельно. Для связи с библиотекой дай ссылку на
   определение компонента либо его путь в каталоге. Связь с кодом указывай только после проверки символа.

## Что передать

- **В ходе разбора** свяжи наблюдения и открытые вопросы с экраном и состоянием. Согласованное решение
  владельца привяжи к существующей карте решений, если она ведётся.
- **Для повторного использования** сохрани запись общего компонента или токена в индексе.
  Правило берётся из `DESIGN.md`, адрес оригинала — из индекса, локальные отличия — из дерева.
- **Фронтенду** передай дерево с привязками к оригиналам. У узла укажи допустимые на экране варианты, состояния
  и переходы. Виды, темы и адаптивность опиши на уровне, где они меняют представление.
  [Формат передачи и пример](references/frontend-handoff.md). Для точечной задачи достаточно изменившейся ветви.

## Ошибки, которые меняют результат

- Если поиск в индексе не нашёл селектор, проверь вложенную группу библиотеки до сборки аналога из поля и иконки.
  Недоступный источник отметь как пробел.
