# Развитие Spydell: этапы и навыки из соседних наборов

## Назначение

Spydell получает недостающие этапы и приёмы из наборов Matt Pocock, OpenSpec, Addy Osmani (agent-skills),
pstack/dyl-stack, superpowers, BMAD/myclaude, startup-team и ponytail, не дублируя их и не заводя второй учёт
рядом с OpenSpec. Реализация инициатив по-прежнему идёт через OpenSpec со схемой `spydell`.

## Состояние

Режим: правка навыков волнами. Решения R1–R4 приняты 2026-10-31 — 2026-11-01.
Волна 1 (зависимости) закоммичена в d66ac90.
Волна 2 (анализ) готова к коммиту: маршрут R6 в SKILL.md и usage.md, лестница и запретный список в method.md,
«нужно ли» в profiles.md, типы вопросов фронтира, реестр упрощений в шаблоне карты, строка «Не проверено», README.
Ревью: F1 major (запретный список не распространялся на маршрут «код»), F2 minor (`shortcut:` в коде),
F5 cosmetic (ссылка на маршруты в sdd-coordination) исправлены; F3 (ponytail ultra на concept) и F4 (лестница
на clarify) отклонены по R2_Q7 и правкам SKILL.md; повторное ревью — готово. Тесты 8/8.

| R6_Q1 | Первое действие Spydell — оценка размера и маршрута одной строкой; по умолчанию самый короткий маршрут, переход дальше только по сигналу. «Сразу код»: локально, поведение однозначно, без продуктового выбора, обратимо, без внешнего контракта, данных и миграций — без документов Spydell и OpenSpec, профильный навык, тесты, итог одной строкой. «Сразу спека»: цель ясна, одна capability или один change, но новое наблюдаемое поведение или контракт — OpenSpec propose/ff без concept, map.md и roadmap; spec-review только при заметном риске. Короткие маршруты убирают документы и церемонии, но не вопросы: неясность поведения, продуктовый выбор или риск — grilling до спеки или кода на любом маршруте, включая «сразу код»; нет неясности и риска — вопросов нет. Вопросы появляются по неясности или риску, а не по маршруту. Полный путь — сырой замысел, несколько capabilities или волн, продуктовые развилки, необратимость, несколько участников; уровни пропорционально. Сигналы перехода: продуктовый выбор, необратимость, расползание на несколько capabilities, неясный критерий успеха — переход объявляется одной строкой. Проверки масштабируются с маршрутом: полный wave-review с QA только для волн полного пути. Карта работы маленькой задачи — одна строка маршрута |

| R7_Q2 | Черновик кейсов — сразу после specs, из стратегии и сценариев; ожидаемые результаты из сценариев. После реализации план дополняется регрессией по diff |
| R7_Q3 | Исполнитель QA — отдельный агент или сессия: план и сборка без контекста реализации. Человек — кейсы с необратимыми действиями и оценкой на глаз |
| R7_Q4 | Масштаб QA по маршрутам: «код» — 1–3 smoke-кейса строкой в итоге, если изменение видно пользователю; «спека» — короткий qa-plan при UI; полный путь — полный план |
| R7_Q5 | Исследовательское тестирование — одна сессия по заданию (что ищем, таймбокс), только для рискованного UI |
| R7_Q6 | Стабильные кейсы переносятся в e2e проекта, если фреймворк уже есть; новый фреймворк ради этого не заводится |
| R7_Q7 | Браузерный инструмент — мягкая зависимость, любой доступный; нет инструмента — статус «заблокирован», план уходит человеку чек-листом |
| R7_Q8 | В плане только ссылки на тестовые аккаунты и сиды; агент может попросить человека подготовить env-окружение (`.env.test`: URL стендов, тестовые аккаунты, ключи тестовой среды). Секреты не попадают в план, отчёт и вывод. Рабочие сервисы — только человек, с разрешения |
| R7_Q9 | Стратегия тестирования — раздел roadmap.md на полном пути (10–15 строк); развилки человека — через grilling (кто выполняет QA, стенды, допустимый риск, нефункциональное, браузеры и устройства, данные, что автоматизировать), факты агент выясняет сам. Влияет на нарезку, зависимости (стенды, данные, ручные ворота как зависимость выпуска) и приёмку срезов. Отдельных волн тестирования нет, кроме блокирующего среза инфраструктуры тестов и регрессии перед выпуском по желанию владельца. С CONSTRAINTS.md не дублировать |
| R7_Q10 | Сначала скрипт: что можно проверить тестом (unit, интеграционный, API, e2e), агент оформляет тестом; ручной прогон — только для визуального, UX, исследовательского или где разовый скрипт дороже пользы. Записать один раз, согласовав с лестницей достаточности |
| R7_Q11 | API: по умолчанию автотесты в проекте; один раз спросить, нужен ли пакет для QA-инженера (коллекция Postman/Insomnia и шаблон окружения без секретов); делать только по «да» |
