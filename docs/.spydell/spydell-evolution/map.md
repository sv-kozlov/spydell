# Развитие Spydell: этапы и навыки из соседних наборов

## Назначение

Spydell получает недостающие этапы и приёмы из наборов Matt Pocock, OpenSpec, Addy Osmani (agent-skills),
pstack/dyl-stack, superpowers, BMAD/myclaude, startup-team и ponytail, не дублируя их и не заводя второй учёт
рядом с OpenSpec. Реализация инициатив по-прежнему идёт через OpenSpec со схемой `spydell`.

| R6_Q1 | Первое действие Spydell — оценка размера и маршрута одной строкой; по умолчанию самый короткий маршрут, переход дальше только по сигналу. «Сразу код»: локально, поведение однозначно, без продуктового выбора, обратимо, без внешнего контракта, данных и миграций — без документов Spydell и OpenSpec, профильный навык, тесты, итог одной строкой. «Сразу спека»: цель ясна, одна capability или один change, но новое наблюдаемое поведение или контракт — OpenSpec propose/ff без concept, map.md и roadmap; spec-review только при заметном риске. Короткие маршруты убирают документы и церемонии, но не вопросы: неясность поведения, продуктовый выбор или риск — grilling до спеки или кода на любом маршруте, включая «сразу код»; нет неясности и риска — вопросов нет. Вопросы появляются по неясности или риску, а не по маршруту. Полный путь — сырой замысел, несколько capabilities или волн, продуктовые развилки, необратимость, несколько участников; уровни пропорционально. Сигналы перехода: продуктовый выбор, необратимость, расползание на несколько capabilities, неясный критерий успеха — переход объявляется одной строкой. Проверки масштабируются с маршрутом: полный wave-review с QA только для волн полного пути. Карта работы маленькой задачи — одна строка маршрута |

## Требования к ревью

Передаются автору перед каждой волной и каждому reviewer вместе с входами.

Проверять всегда:
- Одно правило в нескольких местах (README, шаблон, инструкция схемы, wave-review, usage) совпадает по смыслу и полноте;
  пересказ списка либо полный, либо ссылка на канонический. Повторялся в волнах 1 и 3 → переведён в правило
  AGENTS.md «Правило в нескольких местах»; здесь остаётся ссылкой.
- Правила безопасности (запретный список лестницы, разрешения на рабочие службы) не выпадают на коротких путях.
- Новое каноническое место получает ссылки из всех мест, где о нём раньше говорилось иначе.
- В навыках-специалистах сжатие сохраняет запреты, в которых модели ошибаются (выдумать результат, ослабить условие повышения автономности, пропустить контракт инструмента).
- Относительные ссылки работают — проверялось вручную почти в каждом раунде → переведено в тест `tests/test_docs.py` (LinkTests).
- Маршрут × шаг: условие шага формулируется только в его справочнике, остальные места ссылаются; роль и генерируемые
  артефакты не расходятся (например, кто создаёт tasks). Повторился в волне 5 дважды → правило AGENTS.md усилено
  («условие применимости шага — только в каноническом справочнике»); здесь остаётся ссылкой. В волне 6г повторился
  частичный пересказ перед ссылкой → правило усилено («перед ссылкой — только тема»).
- Своя схема OpenSpec проходит archive без предупреждений: proposal содержит разделы, которые проверяет CLI (Why, What Changes).
- Неполное применение решения: если решение называет несколько целевых файлов, проверены все.
- Граница нового исключения: правило «агент делает сам» в том же абзаце называет унаследованные ограничения
  (запретный список, опрос при неясности или риске).
- Сжатие не теряет правил: удалённая строка либо есть в другом месте основного уровня, либо в detailed/, либо удалена
  как общая практика, которую модель соблюдает без текста (R20_Q2); поведение, в котором модели ошибаются, остаётся.
- Разбор документов программой проверен на реальных документах с несколькими группами строк и таблицами разной формы,
  а не только на одной таблице из теста.
- Пути артефактов приёмки названы в artifacts.md для обоих случаев (с OpenSpec change и без). Повторялся в волне 4
  дважды → переведён в тест `tests/test_docs.py`; здесь остаётся ссылкой.
- Требования AGENTS.md: README в том же коммите, «После 0.4.0», superseded.yaml при переформулировке конфига,
  docs/spydell-openspec-setup.md при изменении схемы, новый навык — openai.yaml и таблицы README.

Не поднимать повторно без нового довода:
- Codex не видит навык из `~/.agents/skills` — видит: CLI skills ставит туда как `universal: Codex`.
- Включать уровни ponytail на этапах Spydell — R2_Q7: уровни не вводятся, «ultra» — правило concept.
- Отдельная строка лестницы для clarify — покрыто типами вопросов и «сначала выясни, нужна ли функция».
- Ссылаться из инструкций схемы на method.md вместо текста — OpenSpec отдаёт инструкции без справочников Spydell,
  они самодостаточны намеренно.
- Номер версии в «После 0.4.0» — версия ставится при выпуске (AGENTS.md).
